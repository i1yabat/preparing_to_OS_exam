# Спецификация тренажёра по операционным системам

Спецификация оформлена после завершения базовой версии. Ниже — требования к
проекту, по которым можно реализовать его с нуля, включая расширение с кешем.

## Цель и сценарии

Студент готовится к экзамену: открывает главную страницу, выбирает тему,
отвечает на вопросы и получает балл с разбором ошибок. Регистрация, история
попыток и редактирование вопросов через веб-интерфейс не входят в объём
работы.

1. На главной студент видит темы и число вопросов. Нажатие на карточку
   открывает тест выбранной темы.
2. В тесте студент выбирает по одному варианту для каждого вопроса и
   отправляет ответы. Если ответ пропущен или недопустим, форма показывает
   ошибку и сохраняет остальные ответы.
3. После корректной отправки студент видит балл и разбор только своих
   ошибок. Можно вернуться к списку или пройти тест заново.

## Критерии приёмки

| ID | Критерий | Как проверить |
| --- | --- | --- |
| A1 | Проект запускается через Docker Compose с Django 5.2, PostgreSQL и Valkey. `web` ждёт готовности обоих сервисов; извне доступен `http://localhost:8001/`. | Запустить из чистой копии по README, проверить `docker compose ps` и HTTP 200 после миграций. |
| A2 | Темы, вопросы, варианты и пояснения хранятся в PostgreSQL с постоянным томом. `demo.json` содержит «Процессы» и «Память», по 5 вопросов в каждой теме, 4 варианта и ровно 1 верный на вопрос. | Применить миграции, загрузить фикстуру, запустить проверки данных; после пересоздания контейнеров с сохранением тома данные доступны. |
| A3 | Главная показывает карточки тем в порядке названий, с количеством вопросов и ссылкой по уникальному slug. Если тем нет, виден текст «Темы пока не добавлены». | Сравнить карточки с фикстурой и проверить пустую базу в тестовом окружении. |
| A4 | По ссылке темы открываются все её вопросы и варианты. В каждом блоке можно выбрать один ответ. После отправки сервер проверяет принадлежность варианта вопросу. | Открыть обе демотемы; в каждой увидеть 5 вопросов и 20 вариантов. Отправить вариант от чужого вопроса: балл не выводится. |
| A5 | Балл — число верных ответов из числа вопросов, без частичных баллов. Для каждого неверного ответа показаны вопрос, верный вариант и пояснение. Есть действия «Пройти ещё раз» и «Вернуться к списку тем». | В теме «Процессы» выбрать варианты № 2, 1, 1, 1 и 2: ожидаются `3/5` и разбор вопросов 2 и 4. Автотестами проверить `0/5` и `5/5`. |
| A6 | Пропуск даёт сообщение рядом с вопросом, форма сохраняет обычные ответы на остальные вопросы, результат не рассчитывается. Недопустимые варианты, лишние вопросы и несколько значений на один вопрос отклоняются. | Пропустить вопрос 3, убедиться в сохранении четырёх выбранных вариантов, исправить пропуск и получить результат. Проверить некорректные отправки тестами Django. |
| A7 | Существующая тема без вопросов показывает «В этой теме пока нет вопросов» и не предлагает отправить форму. Неизвестный slug возвращает HTTP 404. | Проверить пустую тестовую тему и `/topics/unknown/`. |
| A8 | Главная, тест и результат читаются на ноутбуке и телефоне: карточки перестраиваются, длинный текст переносится, варианты и кнопки удобны для нажатия, горизонтальной прокрутки нет. | Проверить в браузере на ширинах 1366, 390 и 320 px. |
| A9 | На промахе кеша главная читает список тем и счётчики одним запросом PostgreSQL и сохраняет результат, в том числе пустой список, в Valkey на 60 секунд. Повторный запрос до истечения TTL получает эти данные из Valkey без SQL-запроса списка. | Удалить только ключ списка, сделать два запроса подряд, проверить TTL в Valkey и число SQL-запросов: `1 → 0`. После истечения TTL следующий запрос снова читает PostgreSQL. |
| A10 | Запуск, загрузка данных, прогон тестов и демонстрация кеша описаны в README. Отчёт отделяет фактически выполненные проверки от инструкции по демонстрации. | Пройти по ссылкам на SDD и воспроизвести команды проверки. |
